# SKYSCRAPER — набор инстументов для работы с комментариями Instagram

Инструмент состоит из двух частей:

* **skyscraper** — авторизуется в Instagram, обходит посты, выгружает комментарии в SQLite или JSONL  
* **analyzer** — читает базу SQLite, позволяет искать, фильтровать и считать статистику по комментариям

Проект написан на Go, управляет реальными браузерами через Chrome DevTools Protocol (chromedp).  
Умеет работать через прокси, сохранять сессию, обрабатывать капчу (ручное вмешательство), раскрывать ответы и подгружать комментарии динамически.

---

## Возможности

**Скрапер**
- Вход в Instagram с сохранением cookies
- Сбор комментариев с одного аккаунта, со списка аккаунтов или из файла со ссылками
- Пул браузеров и вкладок для параллельной обработки
- Автоматическая прокрутка и нажатие «View replies»
- Пакетная запись в SQLite и/или JSONL
- Логирование (уровни DEBUG, INFO, WARN, ERROR)

**Анализатор**
- Просмотр всех комментариев пользователя
- Точный и нечёткий поиск по тексту (Левенштейн)
- Топ активных пользователей
- Комментарии за период
- Частотный словарь слов (с фильтром стоп-слов)
- Посты, отсортированные по числу уникальных комментаторов
- Экспорт результатов в CSV или отдельную SQLite-базу

## Требования

- Go 1.21 или новее
- Установленный Chrome / Chromium (обычно chromedp сам находит его)
- Для работы без графики можно использовать headless, но Instagram часто требует полноценный браузер

## Установка

```bash
git clone https://github.com/yourname/skyscraper.git
cd skyscraper
go build -o scraper ./cmd/scraper   # если main.go лежит в cmd/scraper
```

## Конфигурация

Пример `config.yaml`:

```yaml
scraper:
  base_url: "https://www.instagram.com"
  timeout: 30s
  retries: 3
  user_agents: []
  proxy_list: []
  browser_pool_size: 10          # сколько браузеров одновременно
  max_uses_per_browser: 10       # перезапуск браузера после N вкладок
  max_tabs_per_browser: 2        # вкладок на браузер
  concurrency: 5                 # сколько горутин обрабатывают посты
  output_file: "comments.jsonl"  # если нужен JSONL
  cookies_file: "cookies.json"

database:
  driver: "sqlite3"
  dbname: "instagram_comments.db"

logging:
  level: "debug"
  info_path: "logs/scraper.log"
  error_path: "logs/errors.log"
```

Прокси указываются в `proxy_list` в формате `http://user:pass@ip:port` или `socks5://...`.  
Если список пуст — прокси не используются.

## Запуск скрапера
Для работы достаточно поместить scraper.exe, analyzer.exe и config.yaml в одну директорию. Остальные файлы (логи, база данных, cookies) создадутся автоматически.
### Интерактивный режим
Просто запустите бинарник без аргументов:

```bash
./scraper
```

Будет задано несколько вопросов: логин/пароль, цель сбора (аккаунт или список пользователей/файл), максимальное количество постов, выходной файл, параллелизм, режим хранения.

### Режим командной строки

```bash
./scraper -u mylogin -p mypass -a target_account -max-posts 50 -storage both
```

Основные флаги:

| Флаг | Назначение |
|------|-------------|
| `-u` | Логин Instagram |
| `-p` | Пароль (можно через env `INSTA_PASSWORD`) |
| `-a` | Один аккаунт, с которого собираются посты |
| `-t` | Список аккаунтов через запятую (например `-t "user1,user2"`) |
| `-f` | Файл со списком URL постов (по одному на строку) |
| `-max-posts` | Максимум постов для сбора (0 — все) |
| `-storage` | `file`, `db` или `both` |
| `-o` | Имя выходного файла (для JSONL) |
| `-c` | Количество параллельных воркеров |
| `-no-cookies` | Игнорировать сохранённые куки |
| `-config` | Путь к конфигу (по умолчанию ищется config.yaml в текущей папке) |

Пример сбора всех постов с аккаунта `natgeo` в базу данных:

```bash
./scraper -u mylogin -p mypass -a natgeo -max-posts 0 -storage db
```

Пример сбора комментариев из файла `posts.txt`:

```bash
./scraper -u mylogin -p mypass -f posts.txt -storage both -c 3
```

## Работа с сессией

При первом запуске скрапер запросит логин/пароль, выполнит вход в браузере и сохранит cookies в `cookies.json`.  
В следующих запусках сессия будет использоваться повторно, пока не истечёт или не будет заблокирована Instagram.

Если появилась капча или challenge, скрапер выведет сообщение и будет ждать ручного прохождения в открытом браузере.  
После прохождения нажмите Enter в терминале — он подхватит новую сессию.

## Анализатор

Запускается без аргументов:

```bash
./analyzer
```

Покажет список `.db` файлов в текущей папке, выберите нужный.  
Далее интерактивное меню:

1. **Поиск по тексту** — точное вхождение и нечёткое совпадение (с опечатками)
2. **Все комментарии от пользователя** — вводите имя или выбираете из списка
3. **Топ активных пользователей** — по количеству комментариев
4. **Комментарии за период** — укажите даты в формате ГГГГ-ММ-ДД
5. **Частотный словарь** — топ-50 слов (фильтр стоп-слов, минимальная длина 3 символа)
6. **Посты по уникальным пользователям** — сортировка постов по числу уникальных комментаторов
7. **Сменить базу данных**
8. **Выход**

Любой результат можно экспортировать в CSV или отдельную SQLite-базу.

## Особенности и ограничения

- Instagram активно борется с автоматизацией. Рекомендуется:
  - Использовать качественные прокси (жилые)
  - Не запускать слишком много параллельных вкладок (2–3 на браузер)
  - Делать паузы между аккаунтами
- Если сессия часто слетает — попробуйте `-no-cookies` и авторизуйтесь заново
- Сбор огромного количества комментариев (сотни тысяч) может быть медленным из-за того, что Instagram подгружает их порциями
- Анализатор работает только с SQLite, данные из JSONL придётся импортировать самостоятельно

## Структура проекта (кратко)

```
internal/
  app/          — связывает всё вместе
  browser/      — пул браузеров и вкладок
  config/       — загрузка YAML
  logging/      — логгеры с уровнями
  models/       — структура Comment
  pipeline/     — воркеры: сбор и сохранение
  proxy/        — ротация прокси
  scraper/      — логика обхода Instagram (auth, comments, profile)
  storage/      — file storage (JSONL) и sqlite storage
```

Два внешних `main.go` — собственно скрапер и анализатор.

## Возможные проблемы

**Ошибка «не удалось найти форму входа»**  
Instagram поменял вёрстку. Можно попробовать обновить селекторы в `findLoginForm()`.

**Браузеры не закрываются после остановки**  
Программа пытается корректно завершить все процессы, но если что-то пошло не так — можно вручную убить `pkill -f inst-scraper` (Linux/macOS) или выполнить команду из лога.

**При сборе комментариев мало результатов**  
Проверьте уровень логов (`logging: level: debug`) — возможно, скрипты извлечения перестали работать из-за изменений на сайте.
